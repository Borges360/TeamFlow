# Operational playbooks

Playbooks are optional. Refer to one by name or by a `playbook-*.md` path when a concise operational recipe helps; otherwise a natural-language demand routes directly to the appropriate workflow. A slash-prefixed ID is only a textual prompt shortcut, not a native command. Registry metadata points to one primary workflow and only the selected playbook is loaded. Repository discovery, workspace, branch, pipeline, documentation routing, gates, and review remain workflow/policy responsibilities.

The catalog includes feature, bugfix, tests, technical discovery, performance, ADR, FinOps, documentation, and refactor. Technical discovery is used only when the outcome is known but material solution alternatives or evidence gaps remain; it never implements the product.
