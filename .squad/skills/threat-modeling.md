# Skill: Threat Modeling

## Purpose

Identify realistic abuse and failure paths early enough to change the design.

## Procedure

1. Identify assets, actors, entry points, data classes, trust boundaries, and privileged operations.
2. Map important flows and dependencies at the smallest useful level.
3. Enumerate threats using an approved project method or categories such as spoofing, tampering, repudiation, disclosure, denial, and privilege escalation.
4. Rate likelihood and impact using project criteria; do not invent corporate thresholds.
5. Map prevention, detection, response, and recovery controls.
6. Assign residual risks and validation evidence to owners.

## Output

Threat model with scoped diagrams/tables, control mappings, findings, and Security Gate inputs.
