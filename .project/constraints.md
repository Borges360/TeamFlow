# EXAMPLE CONTEXT — constraints and action boundaries

> Replace with actual organizational, technical, regulatory, cost, access, and change-management constraints.

## Example default boundaries

- Repository read access does not imply write, merge, deploy, production, or external communication authority.
- Production changes, destructive data operations, mainframe batch scheduling, broad infrastructure applies, and irreversible migrations require explicit authorized approval.
- Cross-repository writes require verified owners and an integration plan.
- Secrets, personal data, regulated payloads, and production records must not be copied into prompts or delivery artifacts.
- New recurring cloud cost or a changed SLA requires the accountable owner.
- The example catalogs are not production sources and cannot authorize changes.

## Project values to define

- approved environments and maintenance windows;
- change/deployment approval path;
- data residency and retention;
- repository branching/signing/review rules;
- approved cloud accounts/regions and infrastructure guardrails;
- tool/network access boundaries;
- accessibility and regulatory standards;
- severity and risk thresholds.
